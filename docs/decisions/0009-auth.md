# 0009: OIDC for machines, a proxy secret for the API, an admin session, a visitor sandbox

**Status:** accepted, 2026-11-19

**Context.** Three kinds of caller: Google's scheduler and task queue, the frontend's server, and people (me as admin, and visitors with no login). The original's first production run failed with a 401 because the machine auth had never been exercised before the schedule fired.

**Decision.**
- Dispatch and worker endpoints verify a Google-signed OIDC token: signature, issuer, audience equal to the service URL, email equal to the invoker service account. The verification is the app's own code, tested in CI with tokens signed by a local key against a fake key set, for the accepted case and five refusals.
- The public API accepts only calls carrying a secret shared with the frontend's server, so the limits cannot be skipped by calling Cloud Run directly; the daily cap holds even if the secret leaked.
- Admin: a passphrase checked by the frontend's server, then a signed, HTTP-only session cookie. Shared-state writes need it.
- Visitors: an anonymous signed session cookie that names their sandbox.

**Consequence.** The 401 story is a test, not a memory. The Cloud Run service is open at the platform level, because the frontend cannot mint Google tokens without a long-lived key; every route refuses at the app level instead, and each one is checked in review. The admin passphrase is a single shared secret, which is right for a one-person demo and would be replaced by real identity in a product.
