# 0008: evals scored in code against four bars; labels signed off before any prompt existed

**Status:** accepted, 2026-11-19. Changed in part by [0010](0010-measure-after-the-challenge.md) the same day: forty cases in two sets, harmful counted over everything returned, stability as a share, a rules-only baseline. One sentence below no longer stands: "I am the specialist". The labels were drafted by AI and are reviewed by me, the engineer who built the original system, before any prompt exists; they were not written or reviewed by a deliverability specialist (0010).

**Context.** The original brief names four scores (coverage, precision, harmful, stability over three runs) and fixes two bars. Labels are meant to be what a specialist would flag; I am the specialist. A change that touches the cases, the labels or the bars needs my sign-off, and I want to give it once.

**Decision.** Because risk types are a closed list (0001), all four scores are computed in code from IDs; there is no judge. The bars I chose: coverage at least 0.80, precision at least 0.80, harmful exactly 0, stability at least 18 of 20 cases with the same five IDs in all three runs. The exact definitions are in [docs/EVALS.md](../EVALS.md). The rubric, all twenty labelled cases, the bars and the claim pin are written before any prompt, second-read by a separate agent, and signed off by me. `make check` tests the eval code and runs the plumbing on fixtures with no threshold; `make eval` scores committed recordings for free; `make eval-live` is the paid run; CI runs `make eval STRICT=1` in its own job, which is not a required check.

**Consequence.** The measure is fixed before any prompt exists, so no prompt is written to fit it and it needs no further sign-off later. One known exception: if the first live run scores full marks everywhere, harder cases are required, and those need a new sign-off. The README says the labels were drafted against a written rubric and reviewed by me. Twenty cases is a small set: one case is five points of stability, and the README says so.
