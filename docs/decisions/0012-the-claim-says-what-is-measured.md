# 0012: the claim says what is measured; the comparison with the baseline is evidence, not proof

**Status:** accepted in advance, 2026-11-19 (the limit set after the second challenge, in [0010](0010-measure-after-the-challenge.md)), and applied the same day when the third challenge came back "change needed".

**Context.** The claim first said "judgment-call risks from a model". Three rounds, before any prompt existed, tried to build an eval that a model can pass and a table of thresholds cannot, and each time an independent challenge defeated it with no model:

1. **Twenty cases labelled from the rubric's bands.** About 130 lines of if/else reproduced every label. A rules engine scored full marks.
2. **Ten open cases added**, where the label is a written call that departs from the bands, and a rules-only baseline scored beside the model. Every item the baseline missed was one the bands already call "acceptable", so the baseline made to return one more band (complaints flagged from 0.08%) reached the pass mark with nothing harmful.
3. **Eight harder open cases added and two redrafted**, a four-part rule for "better than the baseline", and a test that no table which also returns any set of "acceptable" bands passes it (8,192 tables). The test holds. But the baseline with one number moved (`volume_spike` raised from a ratio of 1.3 on a domain sending 1,000 messages a week or more) finds 21 of the 25 expected items on the open set with nothing harmful and passes the rule, and it meets all four bars on the forty-eight cases. A review and the challenge each found a table of this kind independently.

Why it kept falling short. Every label, table or open, is a function of a small structured input: thirteen risk types, a dozen numeric fields. Any finite set of such calls can be matched by some table, and with eighteen open cases the table that does it is a short one. Each round closed the gap the last challenge found and left the next-simplest one. The cases were also written by agents, to a brief, with a test to satisfy: the traps ended up paired one to one with the promotions, which defeats exactly the family of tables the test tries. Showing judgment this way would need inputs a table cannot key on (free text, history, context a specialist brings) or labels from specialists on real domains, and the project has neither. I set the limit before the third round: no fourth.

**Decision.**

- **The claim sentence is the fallback wording:** "judgment-call risks picked by a model from a closed list and scored against a written rubric". It is changed together wherever the claim is stated (now `docs/EVALS.md`, the page and the report), as the claim test requires. The sentences that said the open cases show judgment, or that no loosening passes, are removed or corrected wherever they stood, including the rubric and decision 0010.
- **The cases and the baseline stay, as evidence.** All forty-eight cases are scored against the four bars. The rules-only baseline is still scored beside the model, per set, and whether the model does better than it on the open cases is still computed by the four-part rule and reported. It is not a bar and nothing in the claim rests on it.
- **Meeting the bars** no longer requires the model to beat the baseline. If it does not, the README says so.
- **The limits in `docs/EVALS.md` say all of this:** what was tried, in the three steps above; that the unchanged baseline alone meets the four bars (coverage 0.88, precision 1.00, harmful 0, perfectly stable), so the bars show agreement with a written rubric on synthetic cases and not more; that a table with one number moved passes the comparison; where the labels came from; and the six points in decision 0011.

**Consequence.** The honest reading of the evals is narrower than the project set out to show, and the README has to say so in plain words: a reader who asks "why is this not just rules?" gets the answer that, on this evidence, rules would do as well on the risk list, and that what the model adds (the wording a person reads, risks outside any table's foresight) is not measured here. The handled loop, the schedule, the rules engine and the eval harness are unaffected. Revisit if a deliverability specialist labels real domains, or if the model's input gains something a table cannot key on.
